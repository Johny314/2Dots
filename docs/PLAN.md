# 2Dots — план разработки для команды агентов

Читать вместе с [GAME_DESIGN.md](GAME_DESIGN.md) и [ARCHITECTURE.md](ARCHITECTURE.md).

## Принципы параллельной работы

1. **Сначала контракты, потом параллель.** Фаза 0 делается одним агентом; пока она не влита, никого не запускаем.
2. **У каждого агента свои папки.** Чужие файлы не трогать. Нужна правка контракта (`minigame.ts`, `protocol.ts`, `maze/types.ts`) — агент останавливается и пишет об этом в отчёте, а не правит сам.
3. **Каждый агент работает в своём git worktree** (`isolation: "worktree"`), в конце — коммит в свою ветку `phase1/<трек>`.
4. **Готово = команда проверки зелёная.** У каждой задачи есть точная команда приёмки.
5. Сквозная проверка без второго ноутбука: два экземпляра приложения на одном Mac через `127.0.0.1`, либо приложение + `tools/bot.ts`.

## Граф зависимостей

```
Фаза 0 (1 агент) ──┬─► A core/maze ─────────┐
                   ├─► B net + bot ─────────┤
                   ├─► C electron + сборка ─┼─► Фаза 2: интеграция (1 агент) ─► Фаза 3: полировка ∥ релиз ─► Фаза 4: новые мини-игры
                   ├─► D UI экранов ────────┤
                   └─► E рендерер лабиринта ┘
```

## Фаза 0 — Фундамент (1 агент, последовательно) — ✅ выполнена

**Задачи**

1. `npm i -g pnpm`; монорепо: `pnpm-workspace.yaml`, `packages/core`, `packages/net`, `apps/desktop` (шаблон electron-vite, vanilla-ts), `tools/`.
2. Общие `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`), eslint, prettier, vitest в `core` и `net`.
3. Записать контракты из ARCHITECTURE.md дословно: `minigame.ts`, `protocol.ts` (zod), `rng.ts` (mulberry32 + тест детерминизма), `registry.ts`, `games/maze/types.ts`. Для `maze` — заглушка, реализующая интерфейс (`init` ставит игроков в углы, `tick` ничего не делает).
4. `packages/core/src/testing/fake-game.ts` — простейшая мини-игра «счётчик» для тестов сети.
5. Корневые скрипты: `dev`, `typecheck`, `lint`, `test`, `test:e2e`, `bot`, `dist:mac`, `dist:win`.
6. Electron открывает окно «2Dots» с заглушкой; `requestSingleInstanceLock` **не** использовать (нужны 2 экземпляра для тестов).
7. `CLAUDE.md` уже есть — обновить команды, если отличаются. Коммит `chore: scaffold`.

**Приёмка:** `pnpm i && pnpm typecheck && pnpm lint && pnpm test` зелёные; `pnpm dev` открывает окно.

## Фаза 1 — Параллельные треки (5 агентов одновременно)

### A. Логика лабиринта — владеет `packages/core/src/games/maze/**`

- `generateMaze(seed, w, h)` — recursive backtracker на `rng.ts`; опция `braid`.
- `bfsDistance(maze, from)` → массив расстояний; длина пути между стартами.
- Движение: удержание направления, буфер поворота, скорость в клетках/сек через накопление `moveProgress` при фиксированном `dt`, стены блокируют.
- Встреча: одна клетка или соседние без стены (проверка также при «пересечении» за один тик).
- Счёт: режимы `bfs` / `distinct` / `steps`, ничья, таймаут.
- `fogVisible(maze, pos, radius)` — набор видимых клеток (чистая функция, рендерер её использует).
- **Тесты:** один seed → идентичный лабиринт; лабиринт идеальный (связный, рёбер = клеток − 1); стены симметричны у соседей; нельзя пройти сквозь стену; два бота по BFS всегда встречаются, счёт корректен; ничья при симметричной встрече; таймаут.
- **Приёмка:** `pnpm --filter core test` — покрытие `games/maze` ≥ 90%.

### B. Сеть — владеет `packages/net/**`, `tools/bot.ts`

- `HostServer`: `start(port)`, макс. 2 игрока, `hello`/версия, выдача `p1`/`p2`, лобби, `ready` обоих → `start` с seed → отсчёт → цикл тиков `MiniGame` на 30 Гц (через `setInterval` с компенсацией дрейфа) → `state` каждый тик → `end` + счёт матча → `rematch`. Обрыв во время раунда → оставшемуся `aborted`, раунд не засчитан, возврат в лобби, слот свободен (переподключения нет — см. комментарий в `protocol.ts`). Работает с **любым** `MiniGame` из реестра.
- `createGameClient()` — реализация интерфейса `GameClient` из `packages/net/src/client.ts` (интерфейс уже зафиксирован, не менять) на браузерном `WebSocket`; авто-переподключения нет.
- `discovery.ts`: публикация `_2dots._tcp` через `bonjour-service`, поиск 2 с.
- `tools/bot.ts`: `pnpm bot --host 127.0.0.1 [--game maze]` — подключается, жмёт «готов», идёт к сопернику по BFS (видит весь лабиринт — для тестов это нормально).
- **Тесты:** интеграционные на реальных сокетах `127.0.0.1` с `fake-game` (до готовности трека A): лобби, третий игрок отвергнут, неверная версия, мусорное сообщение → `bad_msg`, полный матч, дисконнект.
- **Приёмка:** `pnpm --filter net test` зелёный.

### C. Electron‑оболочка и сборка — владеет `apps/desktop/src/main/**`, `apps/desktop/src/preload/**`, `apps/desktop/electron-builder.yml`, `.github/workflows/**`, `apps/desktop/build/**` (иконки)

- IPC из ARCHITECTURE.md; `hostStart` поднимает `HostServer` + mDNS, возвращает локальные IPv4 (без `127.*`, `169.254.*`).
- `contextIsolation: true`, `nodeIntegration: false`, CSP.
- electron-builder: mac `dmg` arm64, win `nsis` + `portable` x64 (основная цель — Windows-ноутбук девушки); `appId: kz.twodots.game`; без подписи.
- `release.yml`: на тег `v*` и вручную — матрица macos/windows, `pnpm dist:*`, артефакты в GitHub Release.
- `ws` и `bonjour-service` бандлятся в `out/main` (`externalizeDeps: false`): у `ws` есть опциональные нативные `bufferutil`/`utf-8-validate` — убедиться, что сборка их корректно пропускает (или вынести эти два пакета во внешние и упаковать `node_modules`).
- **Приёмка:** `pnpm dist:mac` создаёт `.dmg`; **упакованное** приложение запускается и `hostStart()` реально поднимает сервер (проверить подключением `pnpm bot` или `wscat`); workflow проходит `actionlint`.

### D. Экраны интерфейса — владеет `apps/desktop/src/renderer/src/ui/**`, `apps/desktop/src/renderer/src/style.css`, `apps/desktop/src/renderer/src/main.ts`

- Экраны: Главное (имя, «Создать игру», «Присоединиться»), Хост‑ожидание (показ IP крупно), Присоединение (список найденных + поле IP), Лобби (игроки, выбор мини-игры хостом, «Готов»), Отсчёт, Результат раунда (кто сколько % пути, «Ещё раз»), Ошибка соединения.
- Простой роутер экранов; работает против интерфейса `GameClient` — для разработки мок `ui/mock-client.ts`, реализующий `GameClient` из `@2dots/net/client` (сценарий: лобби → старт → фейковые state → end). Окно игры — пустой `<canvas>` + вызов `GAME_VIEWS[gameId]` из `games/index.ts`, если он есть.
- Имя игрока сохраняется в `localStorage` (в try/catch).
- Стиль: тёмный фон, две яркие точки‑персонажа как айдентика, крупные кнопки, управление с клавиатуры (Enter/Esc).
- **Приёмка:** `pnpm dev` с `?mock=1` — можно прокликать все экраны.

### E. Рендерер лабиринта — владеет `apps/desktop/src/renderer/src/games/maze/**` и регистрацией в `apps/desktop/src/renderer/src/games/index.ts`

- Canvas 2D, devicePixelRatio, масштаб под окно; стены, точки, след, туман войны (через `fogVisible`), HUD (таймер, счёт).
- Визуальный lerp между двумя последними `state`.
- Ввод: стрелки/WASD → `MazeInput` (шлётся при изменении удерживаемого направления).
- Локальный режим `?local=1`: игра крутится в renderer без сети, p1 = WASD, p2 = стрелки — для отладки и визуальной проверки.
- Интерфейс модуля — `MountGameView` из `apps/desktop/src/renderer/src/games/types.ts` (зафиксирован): `mount(canvas, { you, onInput }) → { update(state), destroy() }`; лабиринт берётся из `MazeState.maze`.
- `?local=1` подключается в `main.ts` одной строкой (единственная правка вне своей папки; согласовать с D в Фазе 2, если конфликт).
- **Приёмка:** в `?local=1` можно сыграть раунд вдвоём на одной клавиатуре; скриншот приложен к отчёту.

## Как запускать агентов

**Вариант 1 — вручную, Agent tool.** Фаза 0 одним агентом, затем в одном сообщении 5 агентов с `isolation: "worktree"`. Шаблон промпта:

> Ты — агент трека **{X}** проекта 2Dots. Первым делом в своём worktree выполни `pnpm i` (трекам C/D/E Electron скачается при первом `pnpm dev`). Прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/GAME_DESIGN.md`, раздел «{X}» в `docs/PLAN.md`. Меняй только файлы в своих папках. Контракты не меняй — если нужно, опиши требуемое изменение в отчёте. Закончи, когда команда приёмки зелёная; закоммить в ветку `phase1/{x}`. Отчёт: что сделано, вывод команды приёмки, открытые вопросы.

**Вариант 2 — Workflow.** Напиши «запусти фазу 1 workflow'ом» — будет скрипт: 5 треков параллельно → проверка приёмки каждого → агент‑ревьюер (`code-review`) по каждой ветке → отчёт.

## Скиллы, которые пригодятся

| Скилл                          | Где                                          |
| ------------------------------ | -------------------------------------------- |
| `engineering:architecture`     | ADR по выбору движка/сетевой модели (Фаза 0) |
| `engineering:testing-strategy` | план тестов core/net/e2e                     |
| `workflow-authoring`           | оркестрация пачки агентов                    |
| `run`                          | запуск приложения и проверка руками агента   |
| `code-review`, `simplify`      | ревью каждой ветки перед слиянием            |
| `apple-design`                 | ревью интерфейса (поддерживает Electron)     |
| `engineering:documentation`    | INSTALL.md / README                          |
| `skill-creator`                | скилл `new-minigame` (Фаза 4)                |
