# 2Dots — геймдизайн

Сборник мини-игр для двух игроков по локальной сети (два ноутбука в одной Wi‑Fi).
Каждый игрок управляет точкой на своём устройстве. Первая мини-игра — «Лабиринт».

Решения подтверждены 2026-10-17: счёт по BFS-расстоянию, туман войны включён. Альтернативы остаются в конфиге.

## Мини-игра №1: «Лабиринт» (`maze`)

### Суть

- Вид сверху, сетка-лабиринт (по умолчанию 21×15 клеток).
- Игрок 1 стартует в левом верхнем углу, игрок 2 — в правом нижнем.
- Цель — встретиться. Как только точки встретились, раунд заканчивается.
- Побеждает тот, кто **продвинулся дальше** до встречи.

### Правила (по умолчанию)

| Правило        | Значение по умолчанию                                                                                                                                                                         | Альтернативы                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Тип лабиринта  | «Идеальный» (ровно один путь между любыми двумя клетками), алгоритм recursive backtracker — длинные извилистые коридоры                                                                       | Wilson (равномерный), «braid» — убрать часть тупиков, появятся петли               |
| Генерация      | Из `seed` (одинаковый на обоих устройствах)                                                                                                                                                   | —                                                                                  |
| Встреча        | Игроки в одной клетке **или** в соседних клетках без стены между ними                                                                                                                         | Только одна клетка                                                                 |
| Счёт ✅        | `score = кратчайшее расстояние (BFS) от своего старта до своей клетки в момент встречи`. У кого больше — победил. Равно — ничья. Показывается как «ты прошёл 62% пути»                        | `distinct` — число уникальных посещённых клеток; `steps` — все шаги (с возвратами) |
| Туман войны ✅ | Включён: видно клетки в радиусе 3 + уже посещённые (тусклее). Без тумана игра сводится к «кто быстрее нажимает»                                                                               | Выключен                                                                           |
| Движение       | Клеточное, удержание направления, 7 клеток/сек; буфер поворота (нажал «вверх» заранее — повернёт на ближайшем перекрёстке, как в Pac-Man); разворот назад — мгновенный, даже посреди перехода | —                                                                                  |
| Таймаут        | 3 минуты → ничья                                                                                                                                                                              | —                                                                                  |
| Старт          | Отсчёт 3‑2‑1 после того, как оба нажали «Готов»                                                                                                                                               | —                                                                                  |
| Матч           | До 3 побед (best of 5), после раунда — экран результата и «Ещё раз»                                                                                                                           | Одиночный раунд                                                                    |

Уточнения правил (зафиксированы в Фазе 2):

- **Счёт `bfs`** — BFS‑расстояние от _своего_ старта до _своей_ клетки в момент встречи (не до общей `meetCell`). При встрече в соседних клетках счёты могут отличаться на 1.
- **`meetCell`** (точка встречи для экрана результата): одна клетка — она; соседние клетки — та, у которой `|d1 − d2|` меньше (ближе к «середине» пути между стартами, `d1`/`d2` — BFS‑расстояния от стартов p1/p2); при равенстве — клетка p1.
- **Клетка игрока** — та, из которой он выходит (`x, y`); посреди перехода он ещё «в» ней.
- **Мгновенный разворот:** удержание противоположного направления посреди перехода A → B разворачивает сразу: игрок теперь идёт B → A с прогрессом `1 − moveProgress`, его клетка — B (физическая позиция не меняется). B при этом не попадает в `visited` и не считается шагом; возврат в A — шаг (важно для режима `steps`).
- **Заблокированное удерживаемое направление** продолжает текущее движение (буфер поворота).

Почему счёт по BFS‑расстоянию: в идеальном лабиринте путь между стартами один и тот же для обоих. Кто быстрее и увереннее идёт навстречу, тот встречает соперника ближе к _его_ старту — значит прошёл больше. Блуждание по тупикам не вознаграждается.

### Экран

- Лабиринт по центру, масштаб под окно.
- Своя точка — яркая, у соперника свой цвет. След за точкой (последние ~20 клеток).
- HUD: таймер, счёт матча, имена.
- Управление: стрелки или WASD.

## Каркас для будущих мини-игр

- Каждая мини-игра = модуль, реализующий интерфейс `MiniGame` (см. `ARCHITECTURE.md`) + рендерер.
- В лобби хост выбирает мини-игру из реестра.
- Идеи на потом: «Пятнашки» (догонялки в лабиринте), «Сбор монет», «Пинг‑понг точками», «Не наступи на след» (tron).
